# Label fix of 27 October 2026 (`labels_v2`)

An external code review (Codex) raised three target-definition faults. All three were confirmed
against the code, the database and a fresh Earth Engine recomputation, then fixed on the branch
`worktree-codex-label-fix`. Nothing fitted, logged or deployed on the old labels was overwritten:
every dependent output carries a `_labels_v2` suffix and the unsuffixed files are the pre-fix
history. No model was redeployed.

## The three faults

1. **One-hour window shift.** `IMERG_THAILAND_DATA` (and the Bangkok table) stamp each hour by the
   START of the hour it covers: the half-hours HH:00 and HH:30 are grouped under HH:00. The panel
   loaders built labels with `LEAD 1..h`, so the "next 1 hour" label at issue t was rain in
   [t+1, t+2), not [t, t+1). `Dashboard/verify_imerg.py`, `Dashboard/build_climatology.py` and
   `Dashboard/compare_providers.py` scored the same shifted window, so every number was internally
   consistent but one hour later than the "next h hours" wording in the report and the dashboard.
   The persistence baseline, described as "the last h hours ending at issue time", actually used
   the hour that starts at the issue time.
2. **Cell maximum taken before accumulating.** `precipitation_max_mm` = 0.5·max(first half-hour
   rate) + 0.5·max(second half-hour rate) over the ~9-pixel footprint, where the two maxima can
   sit on different pixels. It is therefore an upper bound on the wettest pixel's hourly total.
   Grid 2, 2026-10-20 14:00 Bangkok: 1.07 mm stored, 0.87 mm at the wettest pixel (the two
   half-hour maxima were on pixels (0,2) and (0,0) of the 3×3 footprint).
3. **Provider comparison misaligned.** Open-Meteo's hourly `precipitation_probability` refers to
   the preceding hour (its documentation: "probability of precipitation with more than 0.1 mm of
   the preceding hour"), so the value stamped issue+k covers [issue+k-1, issue+k). The script
   paired hours 1..h, i.e. [issue, issue+h), with IMERG rows issue+1..issue+h, i.e.
   [issue+1, issue+1+h). Multi-hour provider probabilities were combined as 1 − ∏(1 − p_k), which
   assumes independent hours.

## The corrected label set

`backfill_imerg_pixelmax.py` ran over 2024-06-30 to 2026-10-27 in three parallel workers (about
25 min). Every one of the 16,510,060 complete hours was filled and every stored
`precipitation_max_mm` was reproduced first (0 rows left NULL for a mismatch), so no product
revision contaminates the set. The new value never exceeds the old one (0 rows).

A first pass had to be discarded: it used a lone `ee.Reducer.max()`, which Earth Engine applies
only to pixels whose centre lies inside the cell, and it mis-reproduced 5–30 % of wet rows. The
original fetch combines mean and max, which weights every pixel that touches the cell; the backfill
now uses the same combined reducer.
