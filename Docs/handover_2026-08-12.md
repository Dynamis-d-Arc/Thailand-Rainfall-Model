## 16 — `Thailand_Rain_V8_forecast_gap.py`: the deployability gate

**The reanalysis blocker was a misdiagnosis.** The experiment was built to measure the
ERA5-reanalysis→forecast shift. The `compare` phase against the historical-forecast API
returned r = 1.000 on **all 66 features** over 599,760 June-2026 rows — the "two" datasets are
the same data. Root cause, verified by direct probes on 2024 and 2026 dates:

- The fetch scripts call the archive API **without a `models` parameter**, and its
  `best_match` default for this region resolves to **`ecmwf_ifs`** — Open-Meteo's archived
  ECMWF IFS (analysis + shortest-lead forecast) dataset — **not ERA5**. Explicit
  `models=era5` returns visibly different values.
- The May-2026 live-scraped pilot matches the archive at r = 1.000 (6,384 sampled
  hours × 6 vars), so archived values ≡ what the live API served.
- **Rule for the future: always pass `models=` explicitly.** `best_match` is
  region- and dataset-dependent and silently decides your training distribution.

What remains is a **lead-time gap**: at issue time the newest published IFS run is ~7–13 h
old. Upper-bounded via the previous-runs API (`*_previous_day1` = +24 h staler inputs),
`score prevrun`, June 2026, 148,274 test rows, same fitted model predicting a stacked
[day-0; stale] test matrix so only the inputs move:

| config | ROC gap @ +24 h | h1@1.0mm |
|---|---|---|
| `om_only` | −0.021 to −0.036 | 0.8017 → 0.7658 |
| `hw_offset0h` | **−0.008 to −0.015** | 0.8217 → 0.8064 |

- Driver: IFS precipitation decorrelates with its own previous run at **r = 0.219** (the BKK
  r = 0.18 result was the same phenomenon); all other variable families hold at r ≈ 0.9+.
- The IR features absorb ~60% of the staleness damage — the point of an observation feed.
- **Stale-fed `hw_offset0h` (0.806) still beats fresh-fed `om_only` (0.802)**, and real
  staleness is under half the 24 h bound. Gate passed.
- New tables: `OM_Thailand_Forecast_Data` (null control, = training data) and
  `OM_Thailand_PrevRun_Data` (+24 h lead), each 2026-05-30 → 06-30 × 833 grids, with
  precompute twins built by patched clones of the ERA5 precompute (bit-identical SQL).

## 17 — `Thailand_Rain_V9_2026_decay.py`: the decay is weather, not a defect

All no-training slices over cached OOF/IR arrays; converged in one pass (~10 min).

Elimination chain: **calendar twins kill seasonality** (May–Jun 2025 +0.044 vs May–Jun 2026
+0.023; Jul 2024/25 +0.042/+0.046 vs Jul 2026 +0.015); feed health is clean (hw_valid ~99%,
stable Tb distributions); grader unchanged (IMERG version 07 throughout); provisional-as-such
exonerated a third time (Oct 2025 provisional has the *best* raw IR ROC, 0.82).

The decisive slice: the **untrained** IR signal itself decays (raw ROC 0.72–0.76 → 0.68–0.69),
and the mechanism is rain type — **p(cold-top ≤235 K near cell | labeled rain) fell from 0.85
(2024/25) to 0.72 (2026)**, deep tops (<220 K) from ~0.65 to 0.44–0.60, median cloud-top over
rain events warmed ~211 K → 219–223 K, worsening May→Jul. The weak 2026 wet season (IMERG wet
rates independently ~20% below 2025 twins) produced more **warm/shallow rain, which 10.4 µm IR
physically cannot see**. `om_only` holds because IFS thermodynamics handle warm rain fine.

Consequences: the +0.040 headline is a **convective-regime-weighted average**, not a constant;
nothing needs retraining; **log p(cold-top | rain) monthly in production** — it predicts a
shrinking IR gain before scores show it; the only structural fix is a warm-rain-capable feed
(microwave, or TMD radar if access ever lands). Artifacts:
`trained_models/om_thailand_rain_v9_2026_decay/` (monthly trajectory, grader, regional,
rain-type CSVs).

## 18 — `Thailand_Rain_V10_deploy.py`: artifacts + verified live inference

- **`fit`**: 6 targets on the full IR-covered panel (1,930,894 rows, blocks
  [0,1,5,6,7,11,12] — rows outside them have all-NaN IR and teach nothing), exact V3
  estimator params, 12% isotonic holdout, **F1 thresholds from the OOF probabilities**
  (out-of-fold, uncontaminated by the refit). 6.6 min total. Artifacts:
  `trained_models/om_thailand_rain_v10_deploy/deploy/th_rain_<target>.joblib`, BKK-schema
  dicts, plus `v10_manifest.json` carrying the V8/V9 evidence and library versions
  (pickled under sklearn 1.9.0 — reloading under other versions warns).
- **`parity`** (the part that makes "deployable" a fact): a Python re-implementation of the
  SQL feature pipeline for one issue hour, proven against the SQL precompute at
  **max |diff| = 2.3e-13** (66 features × 833 grids × 3 test hours) and against the cached IR
  block **exactly**. Runs fully offline. If the SQL feature definitions ever change, run this
  before trusting `predict` again.
- **`predict`**: live forecast API (`models=ecmwf_ifs`, past_days=2) + 3 fresh Himawari slots
  from NOAA S3 using the cached V7 masks → nationwide probabilities + flags.
  **First real prediction: 2026-08-11 22:00 local, 2.4 min end-to-end**, output
  meteorologically sensible (monotone across horizons; 91 flagged cells clustered north +
  peninsula — August nighttime monsoon). Each run is self-contained; to refit a target,
  delete its joblib (fit skips existing files).
- **Gotcha: Open-Meteo rate-limits** after heavy use (several hundred calls that day) — the
  live fetcher got HTTP 429 and now retries with exponential backoff (60 s × attempt).
